# Cloudflare Learning Guide

Cloudflareの学習教材を、初学者が読み、試し、あとから参照できる公開サイトとして整備する。

## 成果物の基準

- 各ページは「何のための機能か」を専門用語より先に平易な日本語で説明する。
- 章は独立して参照でき、サイト全体には章一覧と現在地が分かる導線を置く。
- 操作を説明する章は、前提条件、手順、期待結果、確認方法、よくある失敗、後片付けを必要な範囲で示す。
- 読むだけでは理解しづらい通信経路・判断・状態遷移には、意味のある図を添える。既存の正しい図を優先して再利用する。
- PC・SPの両方で横スクロール、読みにくい行長、操作しにくい目次を作らない。HTMLとしてレンダリングされた見た目で確認する。
- 製品名、料金、制限、推奨事項など更新されやすい事実は、公開前に公式一次情報で確認し、基準日または確認日を明記する。

## 作業の進め方

1. 既存の章、目次、画像、公開設定を確認し、ユーザーが指定した範囲だけを対象にする。
2. 初学者が到達すべき理解と、実際に実行できる最小ハンズオンを分けて設計する。
3. ページ分割、見出し、前後移動、目次を整え、単一ページに情報を詰め込みすぎない。
4. 各章を編集する際は、用語を初出時に説明し、設定値・コマンド・期待する出力を区別して示す。
5. 図は説明の代替ではなく補助として使う。図だけでは理解できない前提や判断条件は本文にも書く。
6. 完成後はリンク、画像、Markdown/Jekyllのレンダリング、狭い画面と広い画面の可読性を検証する。

実践手順の詳細とレビュー観点は [references/quality-checklist.md](references/quality-checklist.md) を読むこと。

## 公開時の扱い

GitHub Pagesなど外部公開を行う前に、ローカルの検証結果と公開URLを確認する。外部設定の変更、push、公開はユーザーの依頼範囲に限る。
